# Чыгунка — веб-версия

Железнодорожная настольная игра в духе Ticket to Ride по карте Беларуси (правила v0.3).
Одна статическая страница (HTML + ES-модули, без сборки). Играть можно:

- **по сети** — 2–5 человек, у каждого своя копия страницы; соединение через Supabase;
- **с ботами** — боты работают прямо в браузере хозяина (Лёгкий, Средний, Магистральщик, Сильный, Эксперт);
- **без сети** — вы и 1–4 бота в одном браузере;
- **в демо-сети** — несколько вкладок одного браузера играют «по сети» без Supabase (удобно проверить игру по сети до настройки сервера).

Все правила реализованы сразу, перед партией в лобби выбирается, какие модули включить:
склады и депо (1921), туризм, путевые карты, соседи, конечные станции, наборы маршрутов
(Базовая, Расширенная, Большие города, Мега), цели (3 случайные, выбранные или без целей), дуэль,
сквозной экспресс, строгий исторический режим, быстрая партия, таймер хода.

> **Пошаговая инструкция для новичков — как выложить игру в интернет (Supabase + GitHub Pages): [ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md).**

## 1. Запуск на своём компьютере (за 1 минуту)

Страницу нельзя открыть двойным щелчком по `index.html` — браузер не загрузит модули с диска.
Нужен любой веб-сервер. Проще всего:

```sh
cd chyhunka     # папка с index.html
py -m http.server 8080          # Windows (или: python -m http.server 8080)
python3 -m http.server 8080     # macOS / Linux
```

Откройте <http://localhost:8080>. Игра с ботами и демо-сеть работают сразу, без Supabase.

## 2. Подключение Supabase (≈15 минут, один раз)

1. Зарегистрируйтесь на <https://supabase.com> и создайте проект (**New project**). Регион — ближайший (например, Frankfurt). Пароль базы сохраните, но в игру он не нужен.
2. **Authentication → Sign In / Providers → Anonymous sign-ins** — включите. Игроки входят без регистрации: только имя и код комнаты.
3. **SQL Editor → New query** — вставьте целиком файл `supabase/schema.sql` и нажмите **Run**.
   Скрипт создаёт таблицы, правила доступа (RLS), функции и подключает Realtime. Повторный запуск безопасен.
   Если появилось сообщение «pg_cron недоступен» — включите **Database → Extensions → pg_cron** и запустите скрипт ещё раз
   (это только автоудаление комнат старше 30 дней; игра работает и без него).
4. **Project Settings → API** (или **Data API**) — скопируйте **Project URL** и ключ **anon public** в `config.js`:

   ```js
   export const SUPABASE_URL = 'https://xxxxxxxx.supabase.co';
   export const SUPABASE_ANON_KEY = 'eyJhbGciOi...';
   ```

   Эти два значения публичные — их можно хранить в открытом репозитории.
   **Ключ `service_role` в config.js не вписывайте никогда.**

5. Обновите страницу — на главной появится выбор сервера «Интернет (Supabase)».

> Проверить игру по сети на одном компьютере с Supabase можно только в разных браузерах
> (или в обычном и приватном окне): вкладки одного браузера — это один и тот же анонимный игрок.
> Для проверки в вкладках одного браузера есть демо-сеть.

## 3. Публикация на GitHub Pages (бесплатно)

1. Создайте на GitHub **публичный** репозиторий и загрузите в него содержимое этой папки (вместе с `config.js`).
2. **Settings → Pages → Build and deployment → Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
3. Через минуту игра будет доступна по адресу `https://<ваш-логин>.github.io/<репозиторий>/`.
   Ссылка-приглашение в комнату выглядит так: `…/#/join/K7Q2PX`.
4. Свой домен — **Settings → Pages → Custom domain** (по желанию).

Запасной вариант без git — **Cloudflare Pages → Upload assets**: перетащите папку с игрой в браузер.

### Чтобы бесплатный Supabase не «засыпал»

Бесплатный проект Supabase ставится на паузу после недели без запросов. В репозитории уже есть
задание `.github/workflows/keepalive.yml`, которое раз в 3 дня обращается к базе.
Добавьте секреты репозитория (**Settings → Secrets and variables → Actions → New repository secret**):
`SUPABASE_URL` и `SUPABASE_ANON_KEY` — те же значения, что в `config.js`.
Проверить: **Actions → Supabase keep-alive → Run workflow**.

Если проект всё же уснул, откройте его в панели Supabase и нажмите **Restore** — данные сохраняются.

## 4. Как устроена игра по сети

- **Хозяин** создаёт комнату (код из 6 символов), отправляет друзьям ссылку или код, настраивает места
  (человек / бот / закрыто), цвета и модули, нажимает «Начать партию».
- **Браузер хозяина — арбитр.** Он хранит полное состояние, применяет ходы игровым движком и боты тоже ходят у него.
  Гости пишут в базу только свои действия; хозяин проверяет их и одной транзакцией (`commit_turn`)
  обновляет состояние. Каждый гость видит только свою руку и свои маршруты — это обеспечивают правила доступа базы.
- **Отключения: партия ждёт.** Состояние лежит в Supabase, продолжить можно через час или через несколько дней.
  - перезагрузка страницы в том же браузере — игрок возвращается на своё место автоматически;
  - с другого устройства — «Вернуться в партию» на главной: код комнаты + **код возврата** (вида `2-ABCD2345`, выдаётся при входе);
  - если не в сети хозяин — ходы гостей копятся в очереди и обрабатываются, когда он вернётся;
  - если игрок не вернётся — хозяин нажимает «заменить ботом» у его имени; место можно отдать обратно.
- **Таймер хода** (по умолчанию выключен): по истечении хозяин может сделать ход за игрока ботом «Средний».
- **Реванш**: хозяин создаёт новую комнату с теми же местами и настройками, гости переходят в неё автоматически.
- В конце партии раскрываются все маршруты и `seed` колоды; журнал партии можно скачать в JSON.

**Известное и принятое ограничение:** хозяин технически может подсмотреть чужие карты через инструменты разработчика
браузера — его страница хранит полное состояние. Для игры с друзьями это допустимо (см. ТЗ, раздел 1).

## 5. Интерфейс

- **Правила** (кнопка в верхней панели и на главной) — полные правила с примерами; кнопки «?» в журнале,
  в окне захвата перегона, у целей и в итогах открывают нужный раздел.
- **Журнал**: пиктограмма действия, цвет игрока, цвета взятых карт; наведите на строку — перегон или город
  подсветится на поле, щелчок — поле покажет это место.
- **Ходы соперников и ботов** подсвечиваются на поле: пульсирующий контур цвета игрока, табличка «Имя: +7»
  и паровозик вдоль пути. Карты «летят» из колоды и ряда к руке или к игроку.
- **Настройки** (шестерёнка): скорость анимаций (выкл / 0,3 / 0,6 / 1 с), длительность подсветки (выкл / 3–12 с),
  вид подсветки, звук «ваш ход».
- Окна выбора маршрутов и оплаты открываются сбоку и не закрывают поле; любое окно можно перетащить за заголовок.
- Цвета игроков — неоновые (малиновый, бирюзовый, салатовый, тыквенный, электрик), чтобы не путать с цветами перегонов.

### Оформление поля и украшения

Поле собирается двумя командами из корня проекта (нужны Python 3, numpy, opencv-python, scipy, scikit-image, Pillow):

```sh
python3 tools/board_v2/geo.py          # граница, реки, озёра (Natural Earth) → на схему поля
python3 tools/board_v2/compose.py      # фон: бумага, условный рельеф, леса, болота
python3 tools/board_v2/decorate.py     # подписи рек, масштаб, заливка соседних стран, флаги в ромбах, украшения → img/board_bg.jpg, img/board.svg, data/layout.json
node tools/board_v2/fix_labels.mjs     # (если подписи городов наезжают на вагоны) → src/label_fix.json, затем снова decorate.py
```

Украшения (виньетки, зубр, аисты, паровоз и т. п.) — это список в `tools/board_v2/decor.json` (сейчас пустой).
Картинки лежат в `tools/board_v2/art/`; пример со всеми картинками макета — `decor.example.json`.
Строка списка: `{"art": "bison.jpg", "near": "brest", "width": 42}` — картинка, город (или точка `[x, y]` в мм) и ширина в мм;
место рядом с городом, не закрывающее перегоны и подписи, подбирается автоматически.

Карта меняется только правкой `data/map.json` — код от неё не зависит. Если поменялась геометрия поля,
перегенерируйте раскладку скриптом `tools/make_web_board.py` (в папке с исходниками печатного поля),
положите новые `img/board.svg` и `data/layout.json` в `tools/board_v2/src/` как `board_base.svg` и `layout_base.json`
и заново выполните обе команды оформления.

### Окно «О городе» и открытки

Двойной клик по городу открывает окно с гербом, справкой, достопримечательностью и железнодорожным фактом.
Тексты лежат в `data/cities_info.json` (их можно править в Блокноте). Картинки — в `img/cities/<id>.jpg` (фото, оно же на открытке)
и `img/cities/arms/<id>.png` (герб). Скачать их из Википедии и Викисклада одним разом:

```sh
py tools/fetch_city_images.py        # Windows; на Linux/macOS — python3 tools/fetch_city_images.py
```

Он же скачивает вступление и раздел «История» из статей Википедии в `data/cities_wiki.json` (показываются в окне города со ссылкой на источник).
Если герба города нет, берётся герб района (с подписью); если нет фото — ближайшая к городу фотография с Викисклада.
Скрипт ничего не требует, кроме Python 3, пропускает уже скачанное и записывает авторов и лицензии в `img/cities/credits.json`
(они показываются в окне города). Свою картинку можно положить вручную под тем же именем. Нет файла — игра рисует заглушку.

### Языки

Интерфейс есть на русском, белорусском и английском: выбор — на главной странице и в «Настройках». Полные правила, памятка и тексты о городах пока только на русском.
Код пишет все строки по-русски, перевод подставляется при выводе (`js/i18n.js`, словарь — `js/i18n/dict.js`, собирается из `tools/i18n_dict.json`).
Журнал ходов каждый игрок видит на своём языке. После добавления новых строк: `node tools/i18n_extract.mjs` покажет, чего нет в словаре.

### Пасхалка

Если игрока зовут «Змеючка», клик по его имени показывает всем в комнате случайное фото из `img/kk`. Как добавить фото — в `img/kk/README.txt`.

## 7. Проверки

```sh
npm test                                   # Node 20+: правила, 120 случайных партий, боты, сетевой протокол
PGHOST=localhost PGUSER=postgres sh supabase/tests/run.sh   # схема и RLS на PostgreSQL 15+
node tools/tournament.mjs 400 medium,easy  # турнир ботов
node tools/e2e-demo.mjs                    # две вкладки в настоящем браузере (нужен Playwright)
```

Результаты при сдаче: 22 теста JS, 37 проверок RLS. «Средний» выигрывает у «Лёгкого» 78% партий;
4 «Средних» дают те же показатели, что Python-симуляция (≈170 ходов, медиана отрыва 15 очков, отрыв ≤10 в 36% партий).
То же действие `.github/workflows/test.yml` запускает на GitHub при каждом изменении.

## 8. Лимиты бесплатного Supabase

Ориентиры на середину 2026 года (перед запуском сверьте на <https://supabase.com/pricing>): база 500 МБ,
до 200 одновременных Realtime-подключений, 2 млн Realtime-сообщений и 50 тыс. активных пользователей в месяц
(анонимные тоже считаются), пауза после недели простоя. Партия на 4 игроков — около 10 тыс. Realtime-сообщений,
то есть порядка 200 партий в месяц. Защита от злоупотреблений: не больше 5 комнат в час от игрока,
не больше 10 действий за 5 секунд; при необходимости включите CAPTCHA для анонимного входа
(**Authentication → Attack Protection**).

## 9. Отличия от ТЗ и уточнения правил

- Модуль «События» из ТЗ и «Путевые карты» — одно и то же (12 путевых карт в данных карты), в лобби это один переключатель.
- Наборы маршрутов выбираются одним списком (Базовая / Расширенная / Большие города / Мега), как в правилах, а не галочками.
- Станции в конце партии автоматически используют самый выгодный для игрока чужой перегон.
- Пятое депо (1921) игроки ставят по очереди, начиная с последнего по порядку хода.
- «Со склада» (путевая карта) не тратит ход; «Витрина» заменяет набор карт.
- «Лидер» для путевых карт — все игроки с наибольшим счётом (при ничьей карта действует на каждого).
- Вариант «Заторы» (Минск дороже на 1 карту) не реализован — он не входил в список модулей.
- Интерфейс только на русском; все основные строки собраны в модулях `js/ui/`, перевод на белорусский — после релиза.
