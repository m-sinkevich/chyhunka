# Как выложить «Чыгунку» в интернет — пошагово

Понадобится около 30 минут и два бесплатных аккаунта: **Supabase** (сервер для игры по сети) и **GitHub** (там будет лежать сама страница). Платить ничего не нужно, банковская карта не нужна.

Что получится в конце: ссылка вида `https://ваш-логин.github.io/chyhunka/`, которую можно отправить друзьям.

---

## Часть 0. Подготовка (2 минуты)

1. Распакуйте архив `chyhunka-web.zip`: правой кнопкой → **Извлечь всё…** → **Извлечь**.
2. Внутри появится папка **`chyhunka`**. В ней лежат `index.html`, `config.js` и папки `css`, `data`, `img`, `js` и другие. Дальше мы работаем именно с этой папкой.

---

## Часть 1. Supabase — сервер для игры по сети (15 минут)

### 1.1. Регистрация

1. Откройте <https://supabase.com> и нажмите **Start your project**.
2. Удобнее всего войти через GitHub (**Continue with GitHub**). Если аккаунта GitHub ещё нет, сначала выполните шаг 2.1 из Части 2 и вернитесь сюда. Можно зарегистрироваться и по почте.

### 1.2. Создание проекта

1. Нажмите **New project**. Если Supabase попросит создать организацию, введите любое имя (например, своё) и выберите план **Free**.
2. Заполните:
   - **Project name** — `chyhunka`;
   - **Database Password** — нажмите **Generate a password** и сохраните пароль в заметки. Для игры он не нужен, но пусть будет;
   - **Region** — ближайший к вам, например **Central EU (Frankfurt)**.
3. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создаётся.

### 1.3. Включить вход без регистрации

Игроки заходят в игру только с именем, без паролей. Для этого:

1. В левом меню откройте **Authentication** (значок с человечком).
2. Выберите **Sign In / Providers**.
3. Найдите переключатель **Allow anonymous sign-ins** и включите его.
4. Нажмите **Save** (Сохранить), если такая кнопка есть.

### 1.4. Создать базу данных игры

1. В левом меню откройте **SQL Editor** (значок `>_`).
2. Нажмите **+ New query** (или **New SQL snippet**).
3. На своём компьютере откройте файл `chyhunka\supabase\schema.sql` в Блокноте: правой кнопкой → **Открыть с помощью** → **Блокнот**.
4. В Блокноте нажмите **Ctrl+A** (выделить всё), затем **Ctrl+C** (скопировать).
5. Вернитесь в Supabase, щёлкните в большое поле редактора и нажмите **Ctrl+V**.
6. Нажмите **Run** (или **Ctrl+Enter**).
   - Если появится предупреждение о «destructive operations», нажмите **Run this query**. Это нормально: скрипт безопасен и его можно запускать повторно.
7. Внизу должно появиться **Success. No rows returned**. Готово.
   - Если в сообщениях есть слово **pg_cron**: откройте **Database → Extensions**, найдите в поиске `pg_cron`, включите его и снова нажмите **Run** в SQL Editor. Это нужно только для автоудаления старых комнат, игра работает и без него.

### 1.5. Скопировать адрес и ключ

1. Внизу левого меню нажмите **Project Settings** (шестерёнка).
2. Откройте **Data API** (или **API**) и скопируйте **Project URL**. Он выглядит так: `https://abcdefghijklmn.supabase.co`.
3. Откройте **API Keys**. Нужен ключ **anon public**. Он может лежать на вкладке **Legacy API Keys** и начинается с `eyJ…`. Нажмите **Copy**.
   - Если такой вкладки нет, возьмите **Publishable key**: он начинается с `sb_publishable_…`.
   - ⚠️ Ключ **service_role** или **secret** никуда не копируйте и никому не показывайте.

### 1.6. Вписать адрес и ключ в игру

1. Откройте `chyhunka\config.js` в Блокноте (правой кнопкой → **Открыть с помощью** → **Блокнот**).
2. Вставьте значения **между кавычками**:
   ```js
   export const SUPABASE_URL = 'https://abcdefghijklmn.supabase.co';
   export const SUPABASE_ANON_KEY = 'eyJhbGciOiJIUzI1NiIsInR5cCI6...';
   ```
3. Сохраните: **Ctrl+S**.

Эти два значения публичные: их можно выкладывать в интернет, так задумано.

### 1.7. Проверить на своём компьютере (необязательно)

1. Откройте папку `chyhunka` в Проводнике, щёлкните в адресную строку, наберите `cmd` и нажмите Enter.
2. В чёрном окне выполните `py -m http.server 8080` (если не сработает — `python -m http.server 8080`).
3. Откройте в браузере <http://localhost:8080>. Жёлтого сообщения «Сервер Supabase ещё не подключён» быть не должно, а под именем появится выбор **Сервер: Интернет (Supabase)**.
4. Создайте комнату. Во **втором браузере** (или в приватном окне: **Ctrl+Shift+N**) войдите по коду. Если вы видите друг друга в лобби, всё работает.

Чёрное окно можно закрыть, когда закончите.

## Часть 2. GitHub — размещение страницы (10 минут)

### 2.1. Регистрация

Откройте <https://github.com> → **Sign up**: почта, пароль, логин. **Логин будет частью адреса игры**, выбирайте короткий.

### 2.2. Создать репозиторий (хранилище файлов)

1. Справа вверху нажмите **+** → **New repository**.
2. **Repository name** — `chyhunka`.
3. Выберите **Public** (бесплатные страницы работают только с публичным хранилищем).
4. Остальное не трогайте: галочку «Add a README» **не** ставьте.
5. Нажмите **Create repository**.

### 2.3. Загрузить файлы игры

1. На странице нового репозитория найдите ссылку **uploading an existing file** и нажмите её.
2. Откройте папку `chyhunka` в Проводнике и выделите **всё её содержимое**: **Ctrl+A**. Нужны файлы и папки внутри, а не саму папку `chyhunka`.
3. Перетащите выделенное мышкой в окно браузера, в область «Drag files here».
4. Дождитесь, пока загрузятся все файлы (около 100), и внизу нажмите зелёную кнопку **Commit changes**.
   - Если GitHub пишет, что файлов слишком много (за раз можно до 100), загрузите в два приёма: сначала всё, кроме папки `tools`, потом ещё раз **Add file → Upload files** и перетащите папку `tools`.
5. Проверьте, что в списке файлов репозитория есть `index.html`, `config.js` и папки `css`, `js`, `img`, `data`, `.github`.
   - Если папки `.github` нет, это не страшно: без неё не будет только «будильника» из шага 2.5.

### 2.4. Включить страницу

1. В репозитории откройте вкладку **Settings** (шестерёнка вверху).
2. В левом меню — **Pages**.
3. В блоке **Build and deployment**:
   - **Source** — **Deploy from a branch**;
   - **Branch** — выберите `main` и папку `/ (root)`;
   - нажмите **Save**.
4. Подождите 1–3 минуты и обновите страницу настроек. Вверху появится **Your site is live at `https://ваш-логин.github.io/chyhunka/`**.
5. Откройте эту ссылку. Это ваша игра, её можно отправлять друзьям.

### 2.5. «Будильник» для Supabase

Бесплатный проект Supabase **засыпает после 7 дней без игр**. В игре есть задание, которое раз в 3 дня «будит» базу, ему нужны адрес и ключ:

1. В репозитории: **Settings → Secrets and variables → Actions**.
2. Нажмите **New repository secret**:
   - **Name**: `SUPABASE_URL`, **Secret**: ваш Project URL → **Add secret**.
3. Ещё раз **New repository secret**:
   - **Name**: `SUPABASE_ANON_KEY`, **Secret**: ваш ключ anon (или publishable) → **Add secret**.
4. Откройте вкладку **Actions**. Если GitHub спросит, разрешить ли задания, нажмите **I understand my workflows, go ahead and enable them**.
5. Слева выберите **Supabase keep-alive** → справа **Run workflow** → **Run workflow**. Через минуту появится зелёная галочка ✅.

> GitHub отключает такие задания, если в репозитории 60 дней ничего не менялось, и присылает об этом письмо. Тогда откройте **Actions → Supabase keep-alive** и нажмите **Enable workflow**.
> Если проект всё-таки уснул: зайдите на supabase.com, откройте проект и нажмите **Restore project**. Данные не теряются.

## Часть 3. Как играть

- **Создать партию:** откройте свою ссылку → введите имя → **Создать комнату** → скопируйте ссылку-приглашение и отправьте друзьям.
- **Друзья:** открывают ссылку, вводят имя, нажимают **Войти**.
- В лобби хозяин выбирает модули, добавляет ботов и нажимает **Начать партию**.
- При входе каждый получает **код возврата**, например `2-ABCD2345`. По нему можно вернуться в партию с другого устройства.

## Часть 4. Как обновить игру, когда появится новая версия

1. Распакуйте новый архив.
2. **Скопируйте в новую папку свой `config.js`** из старой, иначе адрес и ключ пропадут.
3. На GitHub в репозитории: **Add file → Upload files** → перетащите содержимое новой папки → **Commit changes**. Файлы с теми же именами заменятся.
4. Через 1–2 минуты откройте игру и нажмите **Ctrl+F5** (обновление без кэша).
5. Если в описании новой версии сказано «обновить базу», повторите шаг 1.4 с новым `schema.sql`.

## Если что-то не так

| Что видно | Что сделать |
|---|---|
| Жёлтое сообщение «Сервер Supabase ещё не подключён» | В `config.js` на GitHub пустые кавычки. Проверьте шаг 1.6 и загрузите `config.js` заново |
| «Нет доступа к комнате» или не получается войти | Не включён анонимный вход (шаг 1.3) |
| Ошибка про функцию или таблицу, например `delete_room` | Не выполнен или устарел `schema.sql`: повторите шаг 1.4 |
| Страница 404 на github.io | Подождите пару минут; проверьте шаг 2.4 и что `index.html` лежит в корне репозитория, а не в папке `chyhunka` |
| Старая версия после обновления | **Ctrl+F5** |
| Всё работало, а через неделю перестало | Проект Supabase уснул: **Restore project** на supabase.com и проверьте шаг 2.5 |
| Нужно проверить игру по сети одному | Два разных браузера или обычное + приватное окно. Две вкладки одного браузера — это один игрок |

**Никогда** не вставляйте в `config.js` и никуда не публикуйте ключи **service_role** и **secret**.
